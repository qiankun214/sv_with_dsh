# ARCH-001 仲裁器系统方案

> 本产物是**样例数据**：用于演示 spec-to-RTL 流程的追溯链，评审记录必须如实标注为样例评审。
>
> 本版按 ② 阶段约定重写：**整体架构 → 功能分解为模块（每个 module 预计 RTL ≤ 500 行）→ 模块间连接**；
> 不重复抄写 `REQ-001` 的端口表；**不定义模块内部结构**（内部功能块/FSM/数据通路留给 ③ 详细设计）。

## 方案概述

一句话方案：**单模块**的等权轮询仲裁器——`rr_arbiter` 内部用一个轮询指针记住「上次授权给谁」，每拍按指针顺序选出一个请求者授权。

- 对外的功能与接口完全由 `REQ-001`（已放行）定义：`F1~F8`、端口、接口不变式 `I1~I4`、5 个时序场景；
- 本方案只回答三件事：**由几个模块实现**、**每个模块负责什么**、**模块之间怎么连**；
- 模块内部怎么实现（指针寄存器、掩码生成、两段优先级编码、输出门控及其关键路径）不在本阶段定义，留给 ③。

系统上下文框图（模块边界与对外连接）见 `ARCH-001-arb-arch/block-diagram.md`（Mermaid + ASCII 两版）。

## 整体架构

- 系统只有**一个 module**：`rr_arbiter`；没有层次、没有子模块、没有跨模块数据流。
- 数据流：请求者 → `req_i[NUM_REQ]` → `rr_arbiter` → `grant_o[NUM_REQ]`（one-hot）+ `grant_valid_o` → 下游资源。
- 控制流：无（无背压、无握手应答、无软件配置）。
- 时钟/复位贯穿：单一 `clk` 域、同步低有效 `rst_n`；模块内部不产生时钟、不做时钟门控、不做跨域同步。
- 为什么这个系统可以只有一个 module：功能总量很小（`NUM_REQ=4` 时是 2 bit 状态 + 4 bit 组合编码），
  预计 RTL 远低于 500 行，见下节。

## 功能点覆盖

| 功能点 | 本方案如何满足 | 备注 |
|---|---|---|
| F1 至多授权一个 | 授权由单一模块产出，`grant_o` 为 one-hot 或全 0 | 由 ③ 落成具体编码 |
| F2 指针决定优先级顺序 | 模块内维护轮询指针，按索引循环顺序给出优先级 | 内部实现细节属 ③ |
| F3 授权后指针推进 | 指针在每次授权后推进到被授权者的下一个索引 | 内部实现细节属 ③ |
| F4 持续请求可重复授权 | 不插入空档、不锁定授权 | 吞吐 1 grant/cycle |
| F5 全 0 请求不授权 | `req_i==0` 时 `grant_o` 全 0、`grant_valid_o` 为 0，且不改变内部公平性状态 | 内部实现细节属 ③ |
| F6 复位后指针为 0 | 同步复位把内部状态清零，释放后第一次授权按索引 0 优先 | ③ 给每个寄存器的复位值 |
| F7 输出无毛刺/振荡 | 输出只依赖被采样的输入与内部寄存状态，无组合反馈环 | ③ 给关键路径分析 |
| F8 复位断言期间不授权 | `rst_n==0` 时输出被强制为「无授权」（`grant_o` 全 0、`grant_valid_o=0`） | 对应接口不变式 `I4` |

> `REQ-001` 的验收标准已按流程扇出到 ⑤（`VP-*` 的 `TC-*`），本文件不引用 AC 编号。

## 功能分解为模块

分解判据：**每个 module 的预计 RTL ≤ 500 行**；超过 500 行必须继续拆，远低于 500 行则不为拆而拆。

| 模块 | 职责（做什么 / 不做什么） | 预计 RTL 规模 | 对应文件 |
|---|---|---|---|
| `rr_arbiter` | **做**：等权轮询仲裁的全部对外功能（`F1~F8`）——接收 `req_i`、产出 one-hot `grant_o` 与 `grant_valid_o`、维护轮询状态、复位语义。**不做**：跨时钟域、背压/流控、软件寄存器接口、请求屏蔽/加权/锁定 | 远低于 500 行（`NUM_REQ=4`，量级 10² 行以内） | `04-rtl/rr_arbiter/rr_arbiter.sv` |

**为何不再拆**（分解依据）：

1. 功能总量小：`NUM_REQ=4` 时内部只有 2 bit 轮询状态 + 约 4 位组合选择逻辑，单文件远低于 500 行门槛；
2. 拆成真实 RTL 子模块会为每个子模块引入端口声明与例化连线，其开销可能超过被拆出的逻辑本身；
3. 子模块化带来的收益（并行开发、复用、独立验证）在本规模下都不成立，且 `REQ-001` 要求黑盒单点验证（见「验证与综合口径」）。

**模块归属**：本设计只有一个 module，`03-design/rr_arbiter/module.yaml` 的 `implements` 应为 `[DES-rra-001]`，
`id_short` 建议 `rra`，`files` 为 `[rr_arbiter.sv]`（③ 创建骨架时落定）。

## 模块间连接

本设计只有一个 module，**无模块间连接**；因此「连接框图 + 模块间接口表」在本设计中为空，理由如上节「为何不再拆」。

| 源模块 | 目的模块 | 信号 | 方向 | 位宽 | 说明 |
|---|---|---|---|---|---|
| — | — | — | — | — | 无模块间连接 |

对外连接（模块 ↔ 外部世界）不在本文件定义：端口、位宽、时钟域、复位值、信号语义与接口协议
**以 `REQ-001` 的「硬件接口」为唯一权威**，③ 的 `DES-rra-001` 逐条落成端口表。本文件不重复抄写，避免两边漂移。

## 接口与协议

- **对外接口**：见 `REQ-001` 的「硬件接口 → 接口信息（端口表）」与「接口协议（输入侧/输出侧/握手/复位/时钟 + 接口不变式 I1~I4）」。
  本文件不复述端口表。
- **模块间接口**：无（单模块）。
- **软硬件接口**：**无**——模块无寄存器/CSR、无总线从接口、无中断、无状态回读；`NUM_REQ` 是唯一的综合期配置，
  运行时软件不参与。与 `REQ-001` 的结论一致。
- **参数**：`NUM_REQ` 默认 4、合法 2~8（`1` 不合法）。本设计的分解与预算按 `NUM_REQ=4` 给出。

## 时钟与复位

| 时钟域 | 频率 | 来源 | 用途 |
|---|---|---|---|
| `clk` | 目标 100 MHz（周期 10 ns） | 系统时钟（外部提供，本模块不产生时钟） | 模块内全部状态寄存器、同步复位采样 |

- 跨时钟域策略：**不涉及**。`req_i`/`rst_n` 与 `grant_o`/`grant_valid_o` 均在同一 `clk` 域；跨域由上游请求者负责（`REQ-001` non-goal）。
- 复位策略：**同步、低有效**（`rst_n`）。复位期间输出为「无授权」（`F8`）；复位释放后第一次授权按索引 0 优先（`F6`）。
  不引入异步复位，避免复位释放的亚稳态风险。
- 时钟门控：不做（`REQ-001` non-goal）。

> ⚠️ **规范依赖标注**：本方案引用 `standards/coding-standard.md` 的默认复位约定（§2.5），
> 该文件当前仍是 **PLACEHOLDER 占位规范**；④ RTL 阶段将被门禁标为「依赖 placeholder 规范」，产物需显式标注。

## 资源与时序预算

预算按 `NUM_REQ=4`、`sky130_fd_sc_hd`（`tt_025C_1v80`）给出；⑥ 用 Yosys + sky130 实测并逐项对照。

| 指标 | 预算 | 依据 |
|---|---|---|
| 面积（sky130 单元数） | ≤ 150 cells（预期 25~60 cells） | 上限沿用 `REQ-001` 约束；⑥ 实测后可在下一版收紧基线 |
| 频率 | 100 MHz（周期 10 ns） | `REQ-001` 时序约束 |
| 时序收敛 | 单周期同步：输入在 `clk` 上升沿采样，输出以 `clk` 为基准在同一周期内有效；须在 10 ns 内满足建立时间 | `REQ-001` 时序约束 |
| 延迟 | `req_i` 被采样后的同一 `clk` 周期内 `grant_o` 有效（0 拍额外延迟） | `REQ-001` F1/F2 |
| 吞吐 | 1 次授权 / 时钟周期 | `REQ-001` F4；无空档、无锁定 |
| 复位后首授权 | 复位释放后第 1 拍即可授权，起始索引 0 | `REQ-001` F6 |
| RTL 规模 | 单 module，远低于 500 行 | 功能分解判据 |

| 项 | 口径 | 说明 |

## 取舍与被否方案

| 方案 | 否决理由 |
|---|---|
| 拆成真实 RTL 子模块（如 `rr_arbiter_ptr` / `rr_arbiter_enc`） | 功能总量远低于 500 行门槛；子模块端口与例化连线的开销可能超过被拆出的逻辑，复用/并行开发/独立验证在本规模下都没有收益。将来若单文件逼近 500 行或需要多实例复用，再按同一判据拆 |
| 在 ② 就定义模块内部功能块（指针/掩码/编码/门控）与数据通路 | 内部结构属 ③ 详细设计的职责；② 提前定义会与 ③ 的实现取舍冲突，也让 ② 的评审焦点从「架构」漂移到「实现」 |
| 固定优先级编码器（固定索引 0 最高） | 高优先级持续请求时低优先级永久饥饿，不满足 `F2`/`F4` 的公平性要求 |
| 授权后强制插入一拍空档再仲裁 | 吞吐减半（0.5 grant/cycle），`REQ-001` 未要求，且无公平性收益 |
| 寄存器输出授权（`grant_o` 打一拍） | 引入 1 拍延迟，与 `REQ-001` 接口协议「输入采样后同一 `clk` 周期内输出有效」冲突 |
| 在 ② 重复维护一份顶层端口表 | 接口以 `REQ-001` 为唯一权威；重复抄写会随评审改动而漂移，评审须比对两处 |
| 支持加权/优先级配置寄存器 | 属 `REQ-001` non-goals，另立需求再做 |
