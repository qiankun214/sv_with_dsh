# ARCH-001 仲裁器系统方案

> 本产物是**样例数据**：用于演示 spec-to-RTL 流程的追溯链，评审记录必须如实标注为样例评审。

## 方案概述

方案一句话：**单模块、组合授权、寄存器只存轮询指针**的等权轮询仲裁器。

- 唯一状态是 `$clog2(NUM_REQ)` 位的轮询指针 `ptr_q`，复位值 0；
- 授权是 `req_i` 与 `ptr_q` 的纯组合函数：以指针为最高优先级起点做**两段优先级编码**
  （先在「指针及以上」段找最低有效请求位，找不到再在「指针以下」段找），得到 one-hot `grant_o`；
- 每拍若存在有效授权，指针更新为 `(grant_idx + 1) mod NUM_REQ`，实现 F3 的轮询推进；
- 组合输出对 `rst_n` 门控：`grant_valid_o = rst_n & |req_i`，`grant_o = grant_valid_o ? grant_int : '0`，
  以满足 REQ-001 F8「复位断言期间即使有请求也不授权」。`rst_n` 是同步信号，组合门控不引入异步路径。

框图见 `docs/diagrams/arch-001-rr-arbiter.md`（Mermaid + ASCII 两版）。

## 功能点覆盖

| 功能点 | 本方案如何满足 | 备注 |
|---|---|---|
| F1 至多授权一个 | `grant_o` 由两段 `ffs`（find-first-set）优先级编码产生，天然 one-hot 或全 0 | AC-5 |
| F2 指针决定优先级顺序 | `mask_lo = (1<<ptr_q)-1`；`hi=req_i&~mask_lo` 为高优先级区、`lo=req_i&mask_lo` 为绕回区 | 索引循环顺序 |
| F3 授权后指针推进 | `ptr_d = (grant_idx + 1) mod NUM_REQ`；无授权时 `ptr_d = ptr_q` | 与 F5「指针不动」同源 |
| F4 持续请求可重复授权 | 指针移动后原请求者降为最低优先级，一轮后重新升为最高 | AC-7 |
| F5 全 0 请求不授权 | `grant_valid_o=|req_i`；`req_i==0` 时 `grant_o=0` 且指针保持 | AC-3 |
| F6 复位后指针为 0 | `ptr_q` 同步复位到 `NUM_REQ'(0)` | AC-6 |
| F7 输出无毛刺/振荡 | `grant_o` 只依赖 `req_i` 与寄存器 `ptr_q`，无组合反馈环 | AC-5 |
| F8 复位断言期间不授权 | `grant_valid_o = rst_n & \|req_i`，`grant_o` 在 `rst_n==0` 时强制全 0 | AC-6、接口不变式 I4 |

## 模块划分

本功能点规模很小，**只设一个模块**（与 `AGENTS.md` §2「顶层模块名 = `04-rtl/` 下的目录名」一致）：

| 模块 | 职责 | 对应文件 |
|---|---|---|
| `rr_arbiter` | 轮询仲裁器的完整实现：指针寄存器、掩码生成、两段优先级编码、授权与 valid 输出 | `04-rtl/rr_arbiter/rr_arbiter.sv` |

模块契约：`03-design/rr_arbiter/module.yaml`（`id_short: rra`）。
本阶段**暂不创建** `03/04/05` 模块骨架：按门禁规则，`04-rtl/<module>/` 一存在就要求同模块详设已 `approved`；
骨架推迟到 ③ 阶段与 `DES-rra-001` 一起建立。

## 接口与协议

顶层端口（REQ-001 已冻结端口表、信号级语义、接口不变式 I1~I5 与 5 个场景时序图，端口表由 `DES-rra-001` 逐条落成）：

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `clk` | in | 1 | 唯一时钟 |
| `rst_n` | in | 1 | 同步复位，低有效 |
| `req_i` | in | `NUM_REQ` | 请求向量 |
| `grant_o` | out | `NUM_REQ` | 授权 one-hot |
| `grant_valid_o` | out | 1 | `(\|req_i) & rst_n` |

- 参数：`NUM_REQ`（默认 4，合法 2~8）。`NUM_REQ=1` 不合法（无轮询语义），编码逻辑假设 `NUM_REQ≥2`。
- 握手/流控：**无背压**。请求者在被授权前保持 `req_i[k]=1`；授权当拍即可撤销请求。
  仲裁器不做「授权后锁定」（no lock），因此同一请求者可在连续周期被重复授权（F4/AC-7）。
- 位宽/字节序：`req_i` bit k ↔ 第 k 个请求者，LSB 为索引 0；纯 bit 向量，无字节序问题。
- 模块间接口：本方案只有一个模块，**无模块间接口**；`rr_arbiter` 的端口即对外接口。
- 软硬件接口：**无**。本模块无寄存器/CSR、无总线从接口、无中断（REQ-001「软硬件接口」与 non-goals）；
  `NUM_REQ` 是唯一的综合期配置，运行时软件不参与。
- 复位语义：`rst_n==0` 时组合输出强制全 0（F8 / I4），与指针寄存器同步清零一起保证复位后首授权从索引 0 起（F6）。

## 时钟与复位

| 时钟域 | 频率 | 来源 | 用途 |
|---|---|---|---|
| `clk` | 目标 100 MHz（周期 10 ns） | 系统时钟（外部提供，本模块不产生时钟） | `ptr_q` 唯一状态寄存器、同步复位采样 |

- 跨时钟域策略：**不涉及**。`req_i` 与 `grant_o` 均在同一 `clk` 域；跨域由上游请求者负责（non-goal）。
- 复位策略：**同步、低有效**（`rst_n`），与 `standards/coding-standard.md` §2.5 的默认一致。
  复位期间 `grant_o` 全 0；复位释放后第一次授权从索引 0 开始（F6）。不引入异步复位，避免复位释放的亚稳态风险。
- 时钟门控：不做（non-goal）。

## 资源与时序预算

| 指标 | 预算 | 依据 |
|---|---|---|
| 面积（sky130 单元数） | 目标 ≤ 150 cells，预期 25~60 cells（`NUM_REQ=4`，`sky130_fd_sc_hd`） | 2 bit 指针寄存器 + 约 4 位两段优先级编码/掩码逻辑；上限沿用 REQ-001 约束 |
| 频率 | 100 MHz（10 ns） | REQ-001 时序约束 |
| 时序收敛 | 单周期同步：输入在 `clk` 上升沿采样、输出以 `clk` 为基准在同一周期内有效；组合逻辑须在 100 MHz（10 ns）周期内满足建立时间 | REQ-001 时序约束 |
| 延迟 | `req_i` 被采样后的同一 `clk` 周期内 `grant_o` 有效（0 拍额外延迟） | F1/F2 |
| 吞吐 | 1 次授权/时钟周期 | F4；无空档、无锁定 |
| 复位后首授权 | 复位释放后第 1 拍即可授权，起始索引 0 | F6 |

⑥ 阶段用 Yosys + sky130 实测单元数/面积，与本表逐项对照；偏差写入 `CHK-rra-001`。

## 取舍与被否方案

| 方案 | 否决理由 |
|---|---|
| 固定优先级编码器（固定索引 0 最高） | 高优先级持续请求时低优先级永久饥饿，不满足 F2/AC-4 |
| 授权后强制插入一拍空档再仲裁 | 吞吐减半（0.5 grant/cycle），REQ-001 未要求，且无公平性收益 |
| 拆出独立子模块 `rr_priority_encoder` | 单模块规模 25~60 cells，拆分带来的端口/集成成本高于收益；待 `NUM_REQ` 显著增大或需要多实例复用时再拆 |
| 寄存器输出授权（`grant_o` 打一拍） | 引入 1 拍延迟，且需额外处理「授权当拍请求撤销」的语义，与 REQ-001 接口协议「输入采样后同一 `clk` 周期内输出有效」冲突；当前组合授权已满足 100 MHz 单周期收敛 |
| 用「优先级掩码寄存器 + 移位」实现指针推进 | 状态与逻辑比特数随 `NUM_REQ` 线性增长，面积大于 `$clog2` 指针方案，无功能收益 |
| 支持加权/优先级配置寄存器 | 属 REQ-001 non-goals，另立需求再做 |
