# 评审清单（评审 skill 的依据）

供 `spec-to-rtl-review` 技能与人类评审者使用。**逐条给结论**，不允许「基本没问题」这种模糊判断：每条都是 `通过 / 不通过 / 不适用`，不通过必须给出具体位置与理由。

## A. 通用（任何阶段产物）

- [ ] front-matter 完整：`id` `title` `status` `owner` `upstream` `artifacts` 都在。
- [ ] `status: approved` 时 `reviewer` 是**真实的人类**，`date` 是真实日期。
- [ ] `upstream` 逐条存在且已 `approved`（不是 `draft`/`in_review`）。
- [ ] `artifacts` 里的路径都真实存在，且内容与该产物描述一致。
- [ ] ID 格式合法、全仓唯一、没有复用已废弃 ID。
- [ ] 正文没有「高性能」「灵活」「适当」这类不可判定的表述（有则必须给出量化标准）。
- [ ] 变更历史/取舍记录在位（改过什么、为什么改）。

## B. ① 功能点

- [ ] 每条验收标准都能被一个 `TC-*` 覆盖（可执行、可观测）。
- [ ] 写了明确的 non-goals。
- [ ] 需求之间无冲突；有冲突则已显式裁决。
- [ ] 约束（面积/功耗/时序/工艺）有数字或有明确的待定项 owner。

## C. ② 系统方案

- [ ] 覆盖声明里的每个 `REQ-*` 都能在方案中找到对应实现路径。
- [ ] 模块划分的模块名与后续 `03-design/<module>/` 目录名一致。
- [ ] 时钟域与复位策略写清楚了，跨域有明确方案（不是「后面再说」）。
- [ ] 接口协议的位宽、字节序、握手时序无歧义。
- [ ] 资源/时序预算有数字，且与需求约束不矛盾。
- [ ] 被否方案写了否决理由。

## D. ③ 详细设计

- [ ] 端口表齐全：方向、位宽、时钟域、复位值、含义。
- [ ] 状态机的状态列表与转移条件构成完备且互斥的覆盖，无死状态。
- [ ] 每个寄存器有复位值；同步/异步选择有理由。
- [ ] 边界条件逐条有处理策略（空/满、同时请求、背压、非法输入）。
- [ ] 位宽推导无隐式截断；溢出/饱和策略明确。
- [ ] 参数有合法范围，非法参数的行为已定义。
- [ ] 所写结构与 `standards/coding-standard.md` 的可综合子集不冲突。

## E. ④ RTL

- [ ] 顶层模块名 = 目录名；端口与详设端口表逐条一致（数量、方向、位宽、命名）。
- [ ] `module.yaml` 的 `implements` 覆盖本模块全部 `DES-*`。
- [ ] 无 latch、无位宽不匹配、无未驱动/未使用信号（lint 无 hard 级告警）。
- [ ] `always_ff`/`always_comb` 用法与规范一致，无阻塞/非阻塞混用。
- [ ] 复位行为与详设一致。
- [ ] 所有 lint 告警为 0 或已在 waiver 中登记且未过期。
- [ ] 文件头注释含对应 `DES-*`。

## F. ⑤ 代码自测

- [ ] 每个 `REQ-*` 至少被一个 `TC-*` 覆盖；每个 `TC-*` 在 `regress.yaml` 有可执行用例。
- [ ] 测试点覆盖了详设里的每条边界条件，而非只测 happy path。
- [ ] 断言（assert）检查的是需求级性质，不只是波形比对。
- [ ] 失败用例有明确诊断输出，不是只打印「FAIL」。
- [ ] 覆盖率（行/翻转）达到 `regress.yaml` 阈值，或已 waiver 并说明。
- [ ] 测试不依赖未在 `regress.yaml` 声明的随机种子（可复现）。

## G. ⑥ 检查汇总

- [ ] `CHK-*` 引用的报告文件都存在，数字与原始报告一致（不允许手抄走形）。
- [ ] lint/综合/覆盖率三类结论齐全，缺项有 skip 说明与原因。
- [ ] 综合结果与 ② 的资源预算对照，偏差有解释。
- [ ] 每条 waiver 有理由、owner、未过期的 `expires`。
- [ ] 与上一版的差异（面积/覆盖率/告警数）有记录。

## H. 放行判定

以下任一条成立 → **不得放行**：

- 存在 hard fail 的门禁项；
- 上游未 `approved`；
- 评审项有未解释的「不通过」；
- 依赖 placeholder 编码规范却未在产物中标注；
- `reviewer` 无法对应到真实的人。
