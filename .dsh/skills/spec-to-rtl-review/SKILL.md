# 评审（反向把关）

对某个阶段（或全流程）的既有产物做**对抗性**核对。依据是 `standards/review-checklist.md`，逐条给 `通过 / 不通过 / 不适用`，不允许「基本没问题」。

## 步骤

```bash
python3 tools/sv.py gate all            # 先让机器把结构/追溯硬伤暴露出来
python3 tools/sv.py trace               # 覆盖矩阵与未覆盖清单
python3 tools/sv.py doctor              # 哪些检查其实没跑过（skip）
```

1. 读 `standards/review-checklist.md`，按 A~H 逐条核对被评审产物对应的章节。
2. 机器能判的（front-matter、ID、断链、TC↔用例映射、waiver 过期）不要靠眼睛，直接引用 `gate`/`trace` 的输出。
3. 机器判不了的（`F*` 是否可验证、端口表是否足够写 RTL、测试点是否覆盖边界、结论数字是否与报告一致）逐条人工核对。
4. 重点找这几类问题：
   - **不可测/不可判定**的表述（「高性能」「适当」「尽量」）；
   - **数字走形**：`CHK-*` 与 `reports/` 原始报告不一致，或面积未与 ② 预算对照；
   - **掩盖 skip**：工具没装却写成「已检查」；
   - **孤立产物**：没有任何下游引用的详设、没有对应测试点的用例；
   - **占位规范依赖**：用着 PLACEHOLDER 规范却没在产物里标注。

## 输出格式

```markdown
## 结论：不通过 / 通过（有保留项）

### 硬伤（阻塞放行）
- <文件>:<位置> — <问题> — <依据条款>

### 待修（不阻塞但有风险）
- …

### 无法验证
- 检查项 — 原因（工具/PDK/环境）

### 放行建议
- 需先修复：…
- 可带风险放行：…（理由与后续 owner）
```

## 纪律

- **不改产物**：评审只出结论与位置，修改由对应阶段技能负责，避免评审者顺手把证据改掉。
- 发现上游未放行却已开工：直接判不通过，并指出该链条上的具体 ID。
- 结论必须可追溯到 checklist 条款或门禁输出，不接受「凭经验觉得」。
