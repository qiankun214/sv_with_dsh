# ① 功能点（Requirements）

**放什么**：项目要做什么，以「一个功能点一份文件」为单位。这是整条追溯链的源头。

## 命名

```
REQ-001-clk-domain.md
REQ-002-burst-split.md
```

- ID：`REQ-<三位序号>`，全仓唯一，**永不复用**。
- 文件名 = `ID + kebab 短描述`，排序即 ID 顺序。
- 新建：`python3 tools/sv.py new req --title "时钟域划分" --slug clk-domain`

## front-matter（必填）

```yaml
---
id: REQ-001
title: 时钟域划分
status: draft            # draft | in_review | approved | superseded
owner: agent
reviewer:                # approved 时必填（人类）
date:                    # approved 时必填
upstream: []             # 功能点是源头，允许为空
artifacts: []
---
```

## 正文该写什么

| 小节 | 要求 |
|---|---|
| 背景与目标 | 为什么需要这个功能点，解决什么问题 |
| 功能描述 | 可验证的行为描述，避免「高性能」这类不可判定的词 |
| **软硬件接口** | 先给结论：**无软件接口就一句结论** + 软件的唯一影响（通常只剩综合期参数）+ 「要加须另立 REQ」的边界，不必列全「无」的表；**有软件接口才详细描述**（寄存器/总线/中断/地址空间/访问属性 + `REGMAP-*`） |
| **硬件接口** | **固定三段式**：① 参数表；② 接口信息（端口表表头 = 端口/方向/位宽/时钟域/复位值/含义；用结构体时另加成员表）；③ 接口协议——**只写接口**（输入侧/输出侧/握手/复位/时钟 + 接口不变式），**不写内部实现与功能映射、不写组合路径延迟**；再按场景分小标题，每个小标题固定为 **WaveDrom 图（只画端口信号）+ 文字说明**；至少覆盖正常授权/多请求竞争/空请求/复位/请求中途增删 |
| 约束 | 面积/功耗/时序/工艺约束 |
| 不做的事 | 明确的 non-goals（至少覆盖软件接口、时钟域、背压/流、配置能力），防止下游自由发挥 |

> **本文档只描述 IPO**：输入 / 处理（`F*`）/ 输出 + 边界。
> **不写验收标准与测试判据**——那是 ⑤ 验证阶段的职责，由它从 `F*`、接口不变式与时序场景**扇出**为验收标准与 `TC-*`。

## 时序图的布局约定

- **目录**：`01-requirements/<REQ 文件名去扩展名>/`，与本 REQ 的 `.md` **同名、同级**；
- **图源**（WaveDrom `.json`）与**渲染产物**（`.svg`）都放该目录，一个场景一对同名文件（`scenario-N-<场景名>.json` ↔ `.svg`）；
- 两件都入库并列入该 REQ front-matter 的 `artifacts`；渲染命令、记法与三个踩坑见该目录内的 `README.md`。

## 门禁

```bash
python3 tools/sv.py gate 01
```

- hard fail：front-matter 字段缺失/非法、ID 重复、`artifacts` 指向不存在的文件。
- warn：本阶段暂无产物；上游覆盖为空。

## 放行

人类评审后把 `status` 改为 `approved` 并填写 `reviewer`、`date`。**只有 approved 才能被 ② 系统方案引用。**
